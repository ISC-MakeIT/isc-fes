# review-tests

このスキルはコードベースのテストに関して包括的にレビューするためのスキル。

## レビュー観点

- 重要なアプリケーションコードがテストされているか。重要度に関しては、テストの重要度セクションを参照すること。
- モックの使用が適切か。モックの使用に関しては、モック戦略セクションを参照すること。
- ロジックの重要なシナリオがテストされているか。クリティカルなエッジケースがカバーされているか。
- テストの分量は適切か。テストの分量に関しては、テストピラミッドセクションを参照すること。

## テストの重要度

1. ロジックが厚く、純粋な関数は常にテストが書かれているべきである
2. ロジックが厚く、純粋な関数でない場合は、ロジック部分を純粋な関数に切り出し、テストを書くべきである
3. ロジックが厚く、純粋な関数でない場合は、ロジック部分を純粋な関数に切り出すことが難しい場合がある。その場合は、モックを活用してテストを書くべきである
4. ロジックが薄い関数は、テストは必須ではない。むしろ、自明なテストは、テストコードの可読性を下げるため、書かない方が良い場合がある。

## モック戦略

- モックは極力使用すべきではない。
- テストの重要度セクションでも記述したが、モックはなるべく避け、ロジックを純粋な関数に切り出すことを優先するべきである。

## テストピラミッド

- 基本的にユニットテストを多く書くべきである
- 統合テストや e2e テストは、導入コストや実行コスト、メンテナンスコストが高いため、導入には慎重になるべきである
