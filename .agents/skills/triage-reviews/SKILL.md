# triage-reviews

GitHub の PR についたレビューを triage するためのスキル。レビュー内容に応じて以下のように triage する。

## ステップ

### 1. レビューの内容を取得する

- GitHub の PR についたレビューの内容を取得する
- GitHub の接続がない場合は、原因を調査したり回避策を探さずに、ユーザーに接続を促すフィードバックを返し、実行を終了する
  - GitHub の接続がない場合は、ほとんどの場合、MCP の認証切れや接続しているワークスペースのミスであるため、ユーザーに接続を促すフィードバックを返すだけで十分である

### 2. レビューの内容を triage する

- レビューの内容をトリアージする
- 以下の分類を行う
  - CRITICAL: PR のマージをブロッキングするような重大な指摘
  - MAJOR: PR のマージをブロッキングするほどではないが、修正が必要な指摘
    - エッジケースのバグ。（エッジケースだとしても、致命的なバグであれば CRITICAL にする必要がある）
  - MINOR: PR のマージをブロッキングするほどではないが、修正が望ましい指摘
- suzuki3jp のレビューの場合は prefix を参考にする。codrabbit の場合は prefix を参考にせずに、レビューの内容を元に triage する
  - suzuki3jp のレビューのよくある prefix は以下の通り
    - CRITICAL: [MUST]
    - MAJOR: [SHOULD]
    - MINOR: [MAY], [IMO], [NITS]
    - [Q] は質問であるためユーザーに回答を促す。[NOTE] は指摘ではないため triage しない

### 3. triage の結果をユーザーにフィードバックする

- triage の結果をユーザーにフィードバックする
- 指摘の内容をフィードバックするべきで、修正の方法をフィードバックするべきではない。

### 4. ユーザーからタスクの作成を依頼された場合は、add-task スキルを呼び出してタスクを作成する
