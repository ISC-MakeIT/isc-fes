# go-review
このスキルは Go 言語で書かれたコードをレビューするためのスキルで、バグ、パフォーマンス、セキュリティ、可読性、保守性などの観点からコードを評価する。

## レビュー観点
優先度順:
- セキュリティ: コードの脆弱性や、リスクを指摘する。特に変更内容が認証・認可に関係する場合重点的に見る必要がある。
- バグ: コードに潜むバグや不具合の可能性を指摘する。
- パフォーマンス: コードのうち著しくパフォーマンスに影響する箇所を指摘する。特に DB アクセスなど 100ms 以上の遅延が発生する可能性がある箇所は重点的に見る必要がある。
- ソフトウェアアーキテクチャ: コードの設計やアーキテクチャに関する指摘を行う。特に、Go における API 設計や、Go における依存関係の管理、ファイル分割などに関する指摘を行う。
- 可読性、保守性: コードの可読性や保守性に関する指摘を行う。このプロジェクトのバックエンドエンジニアは TypeScript になれており、Go は初めてのため、Go のベストプラクティスに沿っていないコードなどは厳しく指摘する。

## レビュー範囲
ユーザーから特に範囲が明示的に示されない場合以下の範囲をレビューする
- 今いるブランチが main 以外の場合で、ローカルに未コミットの変更が存在する場合、ステージング状況に関わらず未コミットの変更をレビューする。
- 今いるブランチが main 以外の場合で、ローカルに未コミットの変更が存在しない場合、今いるブランチと main の差分をレビューする。
- 今いるブランチが main の場合、今存在する /backend ディレクトリ以下をレビューする。

## アウトプット形式
- レビューコメントは以下のセクションに分割される。
  - セキュリティ、バグ
    - コメントには prefix をつける（CRITICAL, HIGH, MEDIUM, LOW）
    - それらがどのような攻撃を可能にするか、またはどのような不具合を引き起こすかを明記する。
  - パフォーマンス
    - コメントには prefix をつける（CRITICAL, HIGH, MEDIUM, LOW）
    - それらを放置するとどの程度のパフォーマンス劣化が引き起こされるか定量的に明記する（~100ms 程度 など）
  - ソフトウェアアーキテクチャ
    - どのように改善すべきかを明記し、必要に応じてコード例を提示する。
  - 可読性、保守性
    - どのように改善すべきかを明記し、必要に応じてコード例を提示する。
