# ISC FES Analytics

学園祭の振り返り用ローカル分析アプリ。Next.js から既存 PostgreSQL を読み取り、Recharts で表示します。既存の frontend / Go API の起動は不要です。

## 起動

Node.js 22 以降、pnpm 10 を使用します。テストには Bun が必要です。

```sh
cd analytics
pnpm install --frozen-lockfile
cp .env.example .env.local
# .env.local の DATABASE_URL をローカル DB に合わせて編集
pnpm dev
```

[http://127.0.0.1:3001](http://127.0.0.1:3001) を開きます。既存の `.env.local` は上書きしないでください。

リポジトリの DB を使用する場合はルートで `docker compose up -d db`。注文・ゲスト分析には既存マイグレーション `000022` まで、履歴による混雑度比較・ゲスト操作の観測には `000025` が必要です。本アプリはマイグレーション・シード・データ変更を行いません。

DB接続情報はサーバーのみで使用します。各取得は `REPEATABLE READ READ ONLY` トランザクション、SQLのタイムアウトは30秒。待受は `127.0.0.1` 限定です。公開用の認証・デプロイ設定はありません。

## ページ

- **ホーム `/`**：全体・店舗・ゲスト・レビュー分析の入口と、混雑度検証・エクスプローラーへのリンク。DBへの接続なしで開けます。各分析ページのロゴと「ホーム」から戻れ、期間・集計間隔を引き継げます。
- **全体分析 `/overview`**：全店舗の累計売上、累計注文件数、累計キャンセル率、累計対面受付率。期間・間隔・売上対象のみを指定し、店舗・メニュー・受付方法・状態による絞り込みを引き継がず、常に全体を集計します。一括CSVと指標ごとのCSVを出力できます。
- **店舗分析 `/stores`**：複数店舗を比較する時間軸の折れ線グラフ。売上、販売点数／受付件数、キャンセル率、対面受付率、ゲスト数、調理／受取待ち／完了／キャンセル時間。時間は平均・中央値・両方から選択。店舗別・メニュー別の表は左端固定の横スクロールで、単価・時間の平均と中央値、率、件数を比較できます。表の店舗名で1店舗に絞り込み。メニュー別の売上／販売数推移は初期上位5件、任意のメニューへ変更可能です。
- **ゲスト分析 `/guests`**：`guests.created_at` の新規・累計登録数、ゲストごとの期間内購入額の平均・中央値・分布、日ごとの購入額、観測時間の平均・中央値・分布、日別表。
- **レビュー分析 `/reviews`**：アプリの利用体験へのレビュー。全体・ゲスト側・店舗側・不明のrating構成比の円グラフ、平均・中央値、区分別の時系列、trigger別統計、コメント一覧。期間・区分・trigger・rating範囲・コメント有無・本文検索で絞り込めます。円グラフの凡例からもratingで絞り込み可能です。
- **混雑度・詳細分析 `/advanced`**：混雑度の検証（初期表示）とエクスプローラーのみ。`?view=congestion` / `?view=explorer` で直接開けます。重複していた概要・売上・メニュー・注文・受付の画面を削除し、P90はエクスプローラーで確認できます。旧 `/?view=overview` や `/advanced?view=overview` は `/overview`、`view=sales` / `view=orders` は `/stores` に条件を引き継いで転送します。`/guest` は既存の `/guests` に転送します。

条件変更は250ミリ秒後に自動反映し、URLに保存します。再集計中は更新前の結果と明示し、CSVを無効にします。「更新」で同じ条件の最新スナップショットを取得します。ページ間では期間と集計間隔を引き継ぎます。

店舗分析の「グラフの集計」で **区間ごと／累積（選択期間の開始から）** を切り替えられます。全店舗・メニューの時系列に反映し、日付が変わっても累積を継続します。売上・販売数・受付数は累計、ゲスト数は開始からの重複を除いた人数、率は開始からの件数で再計算します。平均・中央値も開始からの元の注文を使い、区間ごとの平均・中央値を合算しません。上部指標と表は期間全体の統計のままです。CSVには表示中の集計方法・累積済みの値を出力するので、Notion側の「累積」はオフにしてください。

店舗分析の初期期間は注文の最初の日〜最後の日の翌日0時。ゲスト分析へ直接アクセスした場合は登録の最初の日〜最後の日の翌日0時（最大直近366日）。5分・15分・30分・1時間・1日の集計ができます。ゲストの購入額・観測時間の日別グラフは常にJSTの1日単位です。

## 店舗指標の定義

| 指標                 | 定義                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------- |
| 対象注文             | `orders.created_at >= 開始 AND created_at < 終了`。状態は集計時点の値                             |
| 売上                 | 既定は受取完了注文の `total_amount`。キャンセル以外／全注文に変更可能。決済・入金額ではありません |
| メニュー売上         | 注文に保存された単価＋トッピング単価に数量を乗じる。現在の価格は使用しません                      |
| メニュー絞り込み     | そのメニューを含む注文。売上・数量は該当明細のみ、注文数・時間は注文全体                          |
| 平均単価・単価中央値 | 売上対象の1注文あたり金額の平均・中央値。商品1点あたりではありません                              |
| キャンセル率         | キャンセル件数 ÷ 条件に一致した全受付件数 × 100                                                   |
| 対面受付率（推定）   | `limit_exempted_by_account_id IS NOT NULL` の件数 ÷ 全受付件数 × 100。代理注文からの推定          |
| 調理時間             | 作成→`ready_at`。キャンセル済みを含め、調理完了時刻がある注文                                     |
| 受け取り待ち時間     | `ready_at`→`completed_at`。両時刻がある注文                                                       |
| 注文完了までの時間   | 作成→`completed_at`                                                                               |
| キャンセルまでの時間 | 作成→`cancelled_at`                                                                               |
| キャンセル待ち時間   | `ready_at`→`cancelled_at`                                                                         |
| ゲスト数             | 異なる `guest_id` の数。端末などによる識別子で、人間の実人数とは一致しません                      |

すべて注文作成時刻のバケットに帰属します。期間内の受取・キャンセルイベント件数とは異なり、後日状態が変われば過去の集計も変わります。平均・中央値は元の注文から直接計算し、区間の平均を再平均しません。時間欠測は除外、対象0件の単価・率・時間はNULL（画面「—」、CSV空欄）。数・売上のない区間は0、率・時間のない区間は線をつなぎません。

店舗分析では注文のない店舗も0件として比較表に残します。店舗名は現在の名前、メニュー名は対象注文の最新スナップショット名。メニューごとの時間は注文全体の値で、商品単独の実測時間ではありません。店舗間・メニュー間のゲスト数や時間は合計できません。

## ゲスト指標の定義

- **新規・累計登録**：注文の有無によらず `guests.created_at` を使用。受付方法・購入額の母集団から独立。全期間累計は開始前の登録を加算、期間内累計は0から開始します。各点は表示バケット内の観測済み登録までを含み、未来のバケットはNULL。端のバケットは選択期間との交差範囲だけ集計します。
- **母集団**：既定は選択した受付方法で期間内作成の受取完了注文を持つゲスト。「期間内登録ゲスト」では期間内に登録した全ゲストが対象で、未購入を0円とします。期間外登録者の購入は後者に含めません。
- **ゲスト単位の購入額**：期間内作成の受取完了注文金額をゲスト別・店舗横断で合計し、その合計の平均・中央値を計算。注文単価の平均ではありません。対面の代理注文はゲストIDが共用される可能性があるため、初期はモバイルのみです。
- **日別購入額**：その日のゲストごとの購入合計を集計。購入ゲストの母集団ではその日の購入者のみ、登録ゲストではその日までに登録済みの対象ゲストを使用し、未購入は0円。「対象件数」はこの分母です。期間全体の平均・中央値とは異なります。
- **観測時間**：母集団のゲスト×JSTの1日が1標本。期間内作成の対象注文について、作成・受取完了・キャンセル、その注文をsubjectとする本人の操作ログ（`actor_guest_id = order.guest_id`、`payload_version = 1`）を観測点にします。同日の最初〜最後の観測時刻の差で、夜をまたぐ空白は合算しません。ログがなければ注文の時刻のみ使用します。
- **欠測と未完了**：異なる観測時刻が1点なら不明（NULL）。期間終了までに終了しない注文や翌日に終了する注文がある日は「未完了あり」として既定で除外。条件を変えると2点以上ある未完了の日も観測時間のまま含められます。単独観測と未完了の件数は重複することがあります。

観測時間の平均・中央値はゲスト日を同じ重みで計算します。入退場時刻がないため、**実際の滞在時間ではありません**。スタッフの操作ログだけで滞在を延長しません。期間末で切れた時間やアプリを使わなかった時間は観測できません。ゲスト分析の結果・CSVに個別ゲストID、メール、レビュー本文は含みません。

## レビュー分析の定義

- `reviews.created_at` が開始以上・終了未満の投稿を集計し、未来の投稿や時系列は含めません。ページへ直接アクセスした際の初期期間は、最初のレビュー投稿日から最後の投稿日の翌日0時（最大366日）。他ページから移動した場合は期間と集計間隔を引き継ぎます。
- レビューは**アプリの利用体験**への満足度で、個別店舗・商品の評価ではありません。reviewsに店舗IDがないため、店舗・注文・メニューへの推測による紐付けは行いません。
- 区分はフロントの `QUESTIONNAIRE_AUDIENCE_BY_TRIGGER` に合わせて明示的に分類します。ゲスト側は `cart_item_added` / `order_completed` / `pickup_completed`、店舗側は `store_home_opened` / `menu_created` / `menu_updated` / `menu_deleted` / `topping_created` / `topping_updated` / `topping_deleted`。未知・未設定は「不明」です。任意の投稿者IDから区分を補完しません。
- ratingは1〜5。平均・中央値は該当する元の投稿から計算し、区間別の平均・中央値を平均しません。円グラフは各区分の件数を分母とし、0件なら割合・平均・中央値はNULLです。★4–5・★1–2の割合、コメント率も表示します。
- 空白のみのコメントは「ratingのみ」として扱います。本文検索は大文字小文字を区別しない部分一致で、`%` や `_` は通常の文字。検索・ratingなどの条件は円グラフ・時系列・表・一覧に共通で適用します。
- 同じ人からの複数投稿もそれぞれ1件。アンケートの表示確率が区分やtriggerで異なるため、投稿数やratingを全利用者の満足度としてそのまま一般化できません。
- 一覧は投稿時刻の新しい順に50件ずつ。ページ分割によって集計対象は変わりません。「Notion用レビューCSV」は現在の条件に一致する投稿を、コメントのない投稿も含めて全件出力します。ゲストID・アカウントIDはAPI・画面・CSVに含めません。コメントはプレーンテキストとして表示します。
- レビューCSVは**1行1レビュー**で、列は `名前` / `レビュー元` / `rating` / `投稿日時JST` / `trigger` / `きっかけ` / `コメント`。`レビュー元` はtriggerから判定した「店舗側」「ゲスト側」「不明」です。両側を1つのNotion DBにまとめる場合は区分を「すべて」にして出力し、インポート後に `名前` をタイトル、`レビュー元` をセレクト、`rating` を数値に設定します。その他の絞り込み条件も出力に適用されます。グラフごとの集計CSVと異なり、元の投稿をまとめたCSVです。

## Notion向けグラフCSV

全体分析の「全体の累計CSV（Notion用）」は**1時刻1行**の形式です。金額・注文件数・キャンセル率・対面受付率をそれぞれ別の数値列にし、分母・分子の累計件数、売上対象、期間、生成時刻も含めます。1つのDBで指標ごとにチャートを作る場合は、このCSVが便利です。「名前」はタイトル、「集計時点JST」はテキスト、金額・件数・率は数値に設定し、横軸を昇順にします。店舗・指標のグルーピングは不要です。率は0〜100（25は25%）の数値なので、Notionのパーセント書式でさらに100倍しないでください。指標ごとに別のDBを使いたい場合は各グラフの「CSV」も利用できます。

全体の累計は選択期間の開始から各区間の終了時刻（未満）まで。期間末・現在時刻で最後の区間を切り、未来のポイントは作りません。注文作成時刻を基準に、現在の注文状態と注文時の総額（トッピング込み）で計算するため、当時点の実売上・キャンセル発生時刻の履歴ではありません。売上対象だけを切り替えても、注文件数・各率の分母は全受付のままです。率は全店舗の累計分子÷累計分母で計算し、店舗別・時間別の率を平均しません。注文0件の率は空欄です。**累計済みなのでNotionの「累積」はオフ**にしてください。

各グラフのCSVは、凡例で表示中の系列・条件と同じ計算済み数値を出力します。先頭はヘッダー、1行は時間／区分×系列。単位・条件・期間・集計間隔・生成時刻は各行に繰り返します。カンマ区切り、UTF-8 BOM、数値は記号なし、欠測は空欄。

1. NotionでCSVをインポート。「名前」はタイトル、「日時ラベルJST」「系列」「指標」「単位」はテキスト、「値」「対象件数」は数値に設定します。
2. グラフビューを追加し、横軸「日時ラベルJST」を昇順、縦軸「値」に設定。グループ化が利用できる場合は「系列」を選択します。テキスト型の横軸でグループ化が出ない場合は、系列のフィルターで1系列ずつ表示してください。グラフビューの自動作成はしません。
3. 日時は `YYYY-MM-DD HH:mm` のテキスト。日付型の自動丸めを避け、5分・15分の精度を保ちます。分布グラフは同列に区間を出力するので、先頭番号の昇順に並べます。
4. 平均・中央値・率・累計は計算済み。同一指標・期間・集計間隔だけを表示し、中央値の再集計や率の単純平均をしないでください。**累計CSVでNotionの「累積」はオフ**にします。

Notionは1グラフ200グループ・50サブグループまで。超過時は画面に注意を表示します。CSVを間引くことはありません。期間・間隔・系列を調整してください。Freeプランはグラフ1つ、有料プランは複数利用可能です。再インポートは行追加となるため、古いデータとの重複に注意してください。

表のCSVは検索・ページ分割によらず全行・全列の生値を出力し、ヘッダーに単位を記載。詳細分析の従来CSVは条件の前置き行がある形式なので、Notionには新2ページのグラフCSVを使用してください。

参考：[Notionグラフ](https://www.notion.com/help/charts)、[CSVインポート](https://www.notion.com/help/import-data-into-notion#csv)

## 混雑度・詳細分析

混雑度は実際の行列・調理能力を計測した値ではありません。未調理・未完了・区間内注文数としきい値から3段階に推定し、入力履歴と比較します。既定は未調理3件未満→1、3〜7件→2、8件以上→3。

- 区間終了直前を比較。進行中はDBスナップショット時点で打ち切り、期間前の滞留も含めます。
- `activity_log` の混雑度履歴を使い、開始前の最後の観測を引き継ぎます。履歴なし・同時刻の矛盾は欠測で、現在値から過去を補完しません。
- 店舗・期間・間隔のみを使用し、メニュー・状態・受付方法は使いません。営業時間に期間を絞って比較してください。
- エクスプローラーで指標・切り口・棒／折れ線／面グラフを選べます。詳細分析のP90等もそのまま利用できます。

## 実装・制限・検証

- `src/server/queries.ts`：店舗・メニュー・混雑度のパラメーター化SQL。
- `src/server/guest-queries.ts`：登録・ゲスト別購入・日別観測時間のSQL。
- `src/server/review-queries.ts`：レビューの区分・rating・trigger・時系列集計、コメントのページ分割と全件CSV。
- `src/lib/reviews.ts`：triggerの区分定義・レビュー条件の検証・本文CSV。
- `src/lib/chart-data.ts`：描画系列・欠測と0の区別・Notion CSV共通データ。
- `src/components/reports/`：2ページ共通の条件入力・表・グラフ・CSV・ヘルプ。
- 最大366日、時系列2,000点、店舗×区間20,000点。店舗の明示選択は30件まで。SQL入力・DB更新APIはありません。

```sh
pnpm typecheck
pnpm build
pnpm test
```

DB統合テストは接続先の指定時のみ実行します。

```sh
TEST_ANALYTICS_DATABASE_URL='postgres://isc-fes:devpassword@localhost:5432/isc-fes?sslmode=disable' pnpm test
```

ランダム名の専用schemaに既存マイグレーションとデータを適用し、終了時にそのschemaのみ削除します（schema作成権限が必要）。期間・JST・複数店舗・金額と時間の平均／中央値・欠測・登録累計・未購入・同一ゲストの複数店舗購入・日またぎ・未完了・履歴欠測を実PostgreSQLで検証。CSVはヘッダー・列数・生値・空欄・日本語・式対策を確認します。
