# ISC FES Analytics

学園祭後の振り返り用のローカル分析アプリ。既存の PostgreSQL を Next.js のサーバー側から直接参照し、Recharts で可視化します。既存の frontend / Go API の起動は不要です。

## 起動

Node.js 22 以降、pnpm 10 を使用します。テスト実行時のみ Bun が必要です。

```sh
cd analytics
pnpm install --frozen-lockfile
cp .env.example .env.local
# .env.local の DATABASE_URL をローカル DB に合わせて編集
pnpm dev
```

[http://127.0.0.1:3001](http://127.0.0.1:3001) を開きます。`.env.local` がすでにある場合は上書きせず編集してください。

リポジトリの `compose.yaml` の DB を使う場合は、ルートで `docker compose up -d db` を実行します。DB には既存アプリのマイグレーションを適用してください。このアプリはマイグレーション・シード・データ変更を行いません。注文分析には `000022` まで、混雑度の入力履歴との比較には `000025` が必要です。

接続情報は `DATABASE_URL` のみで、ブラウザーには渡しません。すべての集計は `REPEATABLE READ READ ONLY` トランザクションで実行し、1回の取得内では同一スナップショットを使用します。待受はループバック限定です。公開・デプロイを前提とした認証はありません。

## できること

- **概要**：売上・注文数・キャンセル率・平均完了時間・対面受付率、注文と売上の時系列、状態内訳、店舗ランキング、時間帯別注文。
- **売上・メニュー**：店舗別・メニュー別の売上と販売点数、平均単価、テーブルの検索・並べ替え、行からの絞り込み。
- **注文・受付**：キャンセル率・対面受付率の推移、完了時間の分布、調理・受取待ち時間、平均・中央値・P90、店舗別の比較。詳細テーブルは25指標を横スクロールで表示し、店舗名を固定します。調理・受取待ち・完了時間それぞれの平均・中央値・P90、時間集計の対象件数、状態別件数、売上・平均単価を比較できます。
- **混雑度の検証**：未調理注文数・未完了注文数・区間内注文数のいずれかと任意のしきい値から3段階に推定。入力履歴と比較し、一致率、平均絶対誤差、履歴カバー率、店舗別の過小・過大申告区間を表示。
- **エクスプローラー**：15指標 × 時系列・店舗・メニュー・受付・状態・時間帯・曜日。棒・折れ線・面グラフ、指標上位8店舗の時系列比較。
- **共通条件**：期間、店舗、5/15/30分・1時間・1日の集計単位。詳細条件からメニュー・注文状態・受付方法・売上対象を選択。適用した条件はURLに保存。
- **CSV**：現在の画面の切り口の全件を、適用条件・単位・集計時刻とともに出力。混雑度画面は店舗×区間の比較データを出力します。UTF-8 BOM付き。検索・ページ分割による表示件数には制限されません。

初期期間は注文がある最初の日から最後の日の翌日0時まで（最大直近366日）。条件を変更すると自動で再集計します（連続する入力は250ミリ秒まとめます）。**再集計** で同じ条件のまま取り直すこともできます。再集計中も操作欄を残し、表示中の数値が更新前の結果であることを明示します。**更新** はDBを再参照します。データを静的に固定したい場合はCSVを保存してください。

## 指標の定義

| 指標               | 定義                                                                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 対象注文           | 注文作成日時が開始以上・終了未満。すべて日本時間で表示・日付区分                                                                                     |
| 売上               | 既定は現在の状態が受取完了の注文金額。キャンセル以外・すべての注文に切り替え可能。決済・入金額ではない                                               |
| メニュー別売上     | 注文に保存された単価＋選択したトッピング単価の合計に数量を乗じる。現在のメニュー価格は使わない                                                       |
| メニューの絞り込み | そのメニューを含む注文を抽出。注文数と所要時間は注文単位、売上と販売点数は選択明細のみ                                                               |
| キャンセル率       | キャンセル注文数 ÷ 抽出後の注文数。状態・受付で絞り込むと分母も変わる                                                                                |
| 対面受付率（推定） | `limit_exempted_by_account_id IS NOT NULL` の注文数 ÷ 抽出後の注文数。スタッフ・管理者による代理注文から推定し、対面取引そのものを記録した値ではない |
| 完了時間           | 作成→受取完了。完了注文のみ。平均・中央値・90パーセンタイルを表示                                                                                    |
| 調理時間           | 作成→調理完了。`ready_at` に到達した注文のみ。キャンセル済みも含む。平均・中央値・P90と対象件数を表示                                                |
| 受取待ち           | 調理完了→受取完了。完了注文のみ。平均・中央値・P90と対象件数を表示                                                                                   |
| キャンセル待ち     | 調理完了→キャンセル。キャンセル注文のみ                                                                                                              |
| 利用者数           | 対象注文の異なる `guest_id` の数。人間の実人数ではなくゲスト識別子の数                                                                               |
| 時間帯・曜日       | 複数日を選ぶと各日を合算。1日あたりの平均ではない                                                                                                    |

売上・所要時間は **注文作成時刻の区間** に帰属します。期間内の受取・キャンセルイベント数とは異なります。注文状態は集計時点の値で、後日完了・キャンセルされた場合は過去の集計結果も変わります。

対象が0件の場合、率・所要時間はNULL（画面では「—」、CSVでは空欄）です。未完了の時間を0分として平均しません。店舗名は現在の店舗名、メニュー名は対象注文の最新スナップショット名を表示し、IDで集計します。注文にない店舗・メニューはランキングに現れません。

## 混雑度の読み方

実際の行列、調理能力、スタッフ人数は記録されていないため、**混雑度は推定**です。店舗ごとに実感に合う基準・しきい値に調整してください。

- 区間の終了直前の状態を比較します。進行中の区間はDBスナップショット時点で打ち切り、将来の状態は推測しません。
- 未調理＝作成済みでまだ調理完了していない注文。未完了＝作成済みで完了・キャンセルしていない注文。期間前から残る注文も含めます。
- 入力値は `activity_log` の `payload_version=1` の店舗混雑度履歴を使用。期間開始前の最後の観測を引き継ぎます。
- 履歴導入前・履歴なしは欠測です。現在の `stores.congestion_level` で過去を補完しません。同一時刻に矛盾する入力値がある場合も欠測とします。
- 店舗・期間・集計単位だけを適用し、メニュー・注文状態・受付方法の絞り込みは使いません。
- 既定は未調理注文数が3件未満→1、3〜7件→2、8件以上→3。履歴がある店舗×区間に等しい重みを付けて一致率・誤差を計算します。休止・閉店時間も含まれるため、営業時間に期間を絞って比較してください。

## 実装と制限

- `src/server/queries.ts`：パラメーター化SQLでDB側集計。ユーザーがSQLを入力する機能はありません。
- `src/server/db.ts`：サーバー専用接続プール、読取専用スナップショット、各SQL30秒のタイムアウト。
- `src/lib/filters.ts`：期間・UUID・列挙値・しきい値・集計数を検証。
- `src/components/`：フィルター、ダッシュボード、Recharts、検索・ソート可能な表。
- 最大366日、時系列2,000点、混雑度の店舗×区間20,000点。超過時は店舗を絞るか集計単位を大きくしてください。
- メニューグラフは指標上位20件、店舗比較グラフは指標上位8件。表・CSVには全件を含めます。
- 明細の追加・修正APIはなく、個人ID・メール・レビュー本文は出力しません。

## 検証

```sh
pnpm typecheck
pnpm build
pnpm test
```

`pnpm test` は Bun の単体テストを実行します。DB統合テストは接続先の指定時のみ実行します。

```sh
TEST_ANALYTICS_DATABASE_URL='postgres://isc-fes:devpassword@localhost:5432/isc-fes?sslmode=disable' pnpm test
```

統合テストはランダム名の専用schemaに既存マイグレーションとテストデータを適用し、終了時にそのschemaだけを削除します。接続ロールにはschema作成権限が必要です。集計条件の組み合わせ、期間境界、トッピングの二重計上防止、NULL、JST、P90、過去の滞留、履歴欠測・競合、未来区間を検証します。
